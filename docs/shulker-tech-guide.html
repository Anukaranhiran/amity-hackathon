4 · Errors we hit and how we fixed them (1–7)

Every failure below is real — pulled from the build log of this project. Format: symptom → root cause → fix.

1Giant viewport-filling SVG icons (warning triangle ate the New Scan page)
Symptom
Icons with no intrinsic size stretched to fill flex containers (the notice bar rendered a ~900px triangle).
Root cause
<Icon/> SVGs had no width/height and flex children stretch by default.
Fix
Global CSS safety net capping icon glyphs at 16px + explicit sizes on every icon context; later hardened in the design-system rewrite.
2Unquoted hyphenated object keys broke the TypeScript build
Symptom
tsc syntax errors inside the Icons map after adding arrow-left/arrow-right.
Root cause
JS object literals require quotes for keys that aren't valid identifiers: arrow-left: is illegal; 'arrow-left': is required.
Fix
Quoted all hyphenated keys ('arrow-left', 'chevrons-left', …). Lesson: JSX-adjacent icon maps need identifier-safe or quoted keys.
3Malformed SVG path syntax error in a new icon
Symptom
Build failure pointing at the trash icon definition.
Root cause
Hand-written <path d="…"> contained invalid path commands.
Fix
Rewrote the path set with clean primitives; adopted the shared S props spread ({...S}) so stroke/fill attributes can't drift again.
4Wizard stepper tracked scan phases instead of wizard steps
Symptom
Progress dots on New Scan highlighted the wrong items.
Root cause
The active index was computed with PHASES.findIndex(...currentPhase) (scan-time phases) instead of the wizard's own step state.
Fix
Stepper now compares against the wizard step index; scan phases remain on the run monitor where they belong.
5Mismatched JSX tags crashed the compile
Symptom
JSX parsing error in the API-key section of NewScan.
Root cause
A block opened <div className="field"> but closed with </label>.
Fix
Corrected the closing tag; established the label.field > span + input convention used across all forms since.
6Background dev servers kept dying between terminal commands
Symptom
curl to :8600 worked in one command, connection-refused in the next; in-flight scans never finished.
Root cause
The execution environment reaps background processes between commands; also setsid is unavailable on macOS.
Fix
All verification moved into self-contained scripts (scripts/e2e.mjs, scripts/verify-demo.mjs) that boot services, run checks and tear down within a single process. nohup for the rare long-lived case.
7spec: "sandbox" rejected by the engine
Symptom
API test passing literal "sandbox" as the spec failed OpenAPI parsing.
Root cause
The demo contract is selected with an explicit flag, not a magic string.
Fix
Use useSandboxSpec: true (or fetch /openapi.json from the sandbox). Kept as a documented API contract.

4 · Errors we hit and how we fixed them (8–14)

8Engine needed spec text, not a URL
Symptom
Feeding https://…/openapi.json straight into ScanConfig.spec failed.
Root cause
parseSpecText() parses contract text by design; URL fetching is deliberately a separate, scope-checked step (server-side).
Fix
UI flows fetch/import first (inventory import-url) or use the sandbox flag; the scan endpoint documents that spec is text or useSandboxSpec.
9Stale branding after rename (port 5174 served old title)
Symptom
Browser showed "SentinelAPI" after renaming everything to Shulker.
Root cause
A leftover vite instance on a shifted port was serving a stale process, not the renamed source.
Fix
Killed orphan listeners, re-ran npm run dev; added port checks to the verification routine.
10Workspace links broke after the package rename
Symptom
Cannot find module '@shulker/scanner-core' after renaming packages.
Root cause
npm workspaces symlink node_modules/@shulker/* at install time; renaming package.json names invalidates the links.
Fix
Re-ran npm install at the root to re-link workspaces. Lesson: package renames always require a reinstall in workspaces.
11Hard-coded topbar color rendered grey in the UI (and broke light theme)
Symptom
Header looked like a detached grey slab; light theme showed a dark strip.
Root cause
background: rgba(10,16,28,0.75) literal in .topbar instead of a theme token.
Fix
Full tokenization pass: every surface/text/border now uses semantic CSS variables; topbar uses var(--bg-raised); light theme overrides the same tokens.
12Cannot find name 'go' in Reports page after refactor
Symptom
tsc error TS2304 in Reports.tsx during the UI polish pass.
Root cause
New empty-state added a navigation button but the component only destructured { latest } from context.
Fix
Extended destructure to { latest, go }. Caught by tsc --noEmit before it could ship — exactly why typecheck gates every change.
13External target refused even with authorization checkbox ticked
Symptom
Scanning https://api.github.com was refused despite per-scan confirmation.
Root cause
validateTarget() only allowed loopback/private ranges; the per-scan checkbox alone wasn't meant to unlock public hosts.
Fix
Two-key gate: allowExternal (Settings toggle, DB-persisted) AND per-scan confirmAuthorized must both hold. Refusal matrix added to e2e (14 checks). Budgets, redaction, deterministic verification untouched.
14CLI couldn't reuse scanner-core after the monorepo rename
Symptom
Dynamic import of sandbox modules from cli.ts failed post-rename.
Root cause
Relative dynamic import('../../sandbox/src/server.ts') plus stale workspace links (same class as #10).
Fix
Re-linked workspaces and verified the CLI demo path end-to-end in e2e so the coupling can't silently rot again.
The meta-lesson Every frontend failure was caught by the same three gates: tsc --noEmit, vite build, and the 60-check e2e script. Every backend/scope failure was caught by the authorization matrix in e2e. The tooling investment paid for itself dozens of times over — nothing regressed silently.
