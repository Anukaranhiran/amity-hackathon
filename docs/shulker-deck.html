The problem

APIs trust credentials too much — and that's the breach

  • Attackers don't break crypto. They log in legitimately, then change an ID: /orders/101 → /orders/102 — and read someone else's data.
  • Admin functions are hidden in the UI but unprotected on the server — one PATCH and a user becomes admin.
  • APIs return full database rows — passwordHash included — trusting clients to "ignore" extra fields.
  • Mobile & SPA frontends are not security boundaries. Every hidden capability is directly callable.

OWASP API Top 10 (2023)

API1 BOLA, API3 Data Exposure, API4 Rate Limiting, API5 BFLA — the authorization-flaw family behind most real API breaches.

Why scanners miss them

Classic DAST maps pages, not object ownership. Pentesters cost thousands per engagement. LLM scanners hallucinate findings.

Architecture

Built like a security tool should be built

  • Monorepo, 6 workspaces — scanner-core, shared, sandbox, scan-api, web, CLI.
  • Zero backend npm dependencies — pure Node + node:sqlite. A security tool that doesn't blindly trust its supply chain.
  • One HTTP chokepoint — SafeHttpClient enforces timeouts, 512 KB caps, no redirects, redaction — for every request, no side doors.

Shulker05
Responsible scanning

A scanner that can't be abused as a weapon

  • Hard request budgets — 10–400 requests, enforced in the engine. It cannot flood or DoS a target.
  • Local-only by default — public targets require three deliberate consents (Settings toggle + per-scan authorization checkbox + server validation).
  • Token redaction everywhere — JWTs and keys never appear in evidence, reports, logs or the UI (regex-swept in tests).
  • Polite rate-limit probes — a bounded burst, never a flood.
  • External mode, live-proven — scanned the public Swagger Petstore over HTTPS with a static API key: 19 endpoints, key fully redacted.
  • Built-in templates — Gemini / OpenAI / GitHub / Stripe contracts generated in memory; one click fills target + auth + spec.
